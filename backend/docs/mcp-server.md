### 1단계: 후보군 추출 (pgVector Semantic Search)

- **작업:** 사용자 질의를 벡터화하여 대량의 매물 중 유사도가 높은 후보를 뽑습니다.
- **기술:** `pgVector`, `Metadata Filtering` (인덱스 최적화).
- **결과:** 유사도 상위 **30개**의 매물 ID 및 시맨틱 텍스트 리스트.

### 2단계: 정밀 재검색 및 필터링 (Reranker)

- **작업:** 가벼운 벡터 검색의 한계를 보완하기 위해 Cross-Encoder로 정밀 비교를 수행합니다.
- **기술:** `FastAPI (Reranker Server)`, `Cross-Encoder`.
- **결과:** 정밀 유사도 점수 산출 및 상위 **10개** 매물 선별.

### 3단계: 품질 검증 및 피드백 (Guardrail)

- **작업:** 검색된 결과가 사용자의 의도와 충분히 부합하는지 점수를 체크합니다.
- **로직:** 상위 3개 매물의 점수가 임계치(Threshold) 미달 시 → **LLM이 재질의 유도** (루프 백).

### 4단계: 상세 데이터 보강 (PostgreSQL Enrichment)

- **작업:** 선별된 10개 ID를 기반으로 DB에서 실제 서비스에 필요한 상세 스펙을 가져옵니다.
- **데이터:** 좌표(위경도), 가격, 면적, 층수 등 MCP 툴 호출을 위한 기초 파라미터 확보.

### 5단계: 지능형 도구 활용 (MCP Server Interaction) 🚀

- **작업:** LLM이 스스로 판단하여 외부 API 및 데이터 기반 분석 도구를 호출합니다.
- **제공 툴(Tools):**
    - **`findCommuteTimeAndCost`**: Odsey API 연동, 출퇴근 시간/비용 계산.
    - **`findFacilityCountAndDistance`**: 주변 인프라(편의점, 병원 등) 밀집도 및 거리 분석.
    - *(확장)*: 지역구별 통계 및 실거래가 추이 분석 툴.

### 6단계: 최종 큐레이션 및 답변 (Final Generation)

- **작업:** MCP를 통해 얻은 동적 정보(출퇴근 등)와 매물 정보를 종합하여 최종 추천을 수행합니다.
- **출력:** 10개 중 최적의 **3개 매물** 선정 + 매물 ID + 개인화된 추천 사유(1줄 요약).
